# Attack-Chain-Visualizer 开发文档

> 项目定位：**把渗透报告里最难写的部分——「这五个漏洞怎么串成一条路」——变成一张图，并算出防守方该在哪一点设卡。**
> 一句话价值：输入攻击技术节点，自动生成攻击路径图 + ATT&CK 映射 + 最短路径与单点故障分析。
> 技术栈：Python 3.10+ / NetworkX 3.x / Graphviz / PyYAML
> 适用：红队演练方案、SRC 漏洞报告、护网复盘、面试作品集

---

## 一、为什么做这个（面试怎么讲）

渗透岗面试最常问的一道题：**「你怎么组织攻击链？」**

绝大多数候选人的回答是一段文字：「先打外网 Web 拿到 shell，然后提权，再横向，最后到域控。」

这句话技术上没错，但**没有信息量**——它没说清楚：

- 哪一步是**必经之路**，防守方在那一点设卡我就断了？
- 如果我准备的**备用路径**是什么？
- 每个节点对应 **ATT&CK 哪个技术编号**？（这是防守方建规则的锚点）

本项目把这三个问题变成可计算的结果。

### 与其他工具的差异化

| 工具 | 能做什么 | 局限 |
|---|---|---|
| AttackIQ / XM Cyber（商业） | 攻击路径模拟与可视化 | 闭源、要钱、定制化难 |
| BloodHound | 图谱能力强 | **只管 AD 域一层**，不管 Web 打点到域控的完整链 |
| 手工 draw.io | 画图自由 | **不能算最短路径、不能算单点故障、不能对 ATT&CK 做映射** |
| **本项目** | 图 + 算法分析 + ATT&CK 映射 | 数据模型简单，够用即可 |

**核心差异：不是画图工具，是「路径分析工具」。** 图只是输出，分析才是价值。

## 二、功能需求（MVP → 进阶）

### MVP（第 1 天必须完成）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F1 | YAML 定义攻击链节点 | 能解析含 5+ 节点的 YAML，字段完整校验 |

### 进阶（第 2 天）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F6 | 备用路径校验 | 至少两条**互不重叠**的路径（节点集合交集为空）才算合格 |

- ❌ 与真实扫描器联动 —— 后期再说

### 分层设计原则

- **model.py 不依赖任何第三方库**——纯 dataclass，方便单测和复用
- **analyze.py 只依赖 networkx**——所有算法集中在这里，方便面试讲
- **render.py 只依赖 graphviz**——渲染失败不影响分析结果
- **attck.py 用 JSON 存数据**——不打进代码，方便对照官方更新

## 四、数据模型设计

### 4.1 节点（Node）

```python
@dataclass
class ChainNode:
    id: str                      # 唯一标识，如 "webshell-upload"
    name: str                    # 显示名，如 "上传 Webshell"
    tactic: str                  # ATT&CK 战术，如 "Initial Access"（TA0001）
    technique: str               # 技术编号，如 "T1190"
    kind: str                    # node 类型：entry/ foothold/lateral/objective/optional
    requires: List[str]          # 前置节点 id 列表（入边）
    optional: bool = False       # 是否为可放弃节点
    detectability: str           # high / medium / low —— 防守方对本节点的检测能力
    detect_tips: List[str]       # 具体检测手段（如 "Web 日志查上传目录"）
    impact: int = 1              # 权重，用于计算路径成本
    note: str = ""               # 备注/踩坑记录
```

**`detectability` 字段是这个项目的灵魂**——它把「攻击链」和「防守盲区」在同一个数据模型里关联起来。

### 4.2 边（Edge）

```python
@dataclass
class ChainEdge:
    src: str
    dst: str
    condition: str = ""          # 前置条件，如 "需要 Administrator 权限"
    fail_rate: float = 0.3       # 该跃迁的失败概率（默认经验值）
    note: str = ""
```

### 4.3 输入 YAML 格式（用户实际写的东西）

```yaml

  name: Webshell 到域控的完整攻击链
```

## 五、核心算法设计（面试重点讲这四个）

### 算法 1｜最短路径分析

**问题**：从任一 entry 节点到任一 objective 节点，哪条路最短？

**实现**：
```python
import networkx as nx

def find_shortest_path(g, entries, objectives, weight="impact"):
    """多源最短路径：在入口集合和目标集合之间找加权最短路径"""
    # 用 super-source 连接所有入口，避免逐个跑最短路
    super_src = "__ENTRY__"
    for e in entries:
        g.add_edge(super_src, e, cost=0)
    return nx.shortest_path(g, super_src, objectives, weight=weight)
```

**关键点**：用超级源节点（super-source）统一处理多入口，比循环跑 N 次 `shortest_path` 更快更优雅。**这个技巧是面试加分项。**

### 算法 2｜单点故障（SPOF）分析

**问题**：哪些节点一旦被打掉，整条链就断了？

**实现思路**：
```python
def find_spof(g, entries, objectives):
    """节点删除法：逐个移除节点，看还存不存在 entry→objective 的完整路径"""
    spof = []
    for node in list(g.nodes()):
        if node in entries or node in objectives:
            continue          # 入口和目标本身不算 SPOF
        g_copy = g.copy()
        g_copy.remove_node(node)
        if not any(nx.has_path(g_copy, e, o) for e in entries for o in objectives):
            spof.append(node)
    return spof
```

**复杂度警告**：`O(V × (V + E))`，节点超过 50 个会明显变慢。**优化方向**：先做一次 `articulation_point`（割点）预筛，只对割点做验证。这是能写进 README 的性能优化点。

### 算法 3｜备用路径校验（两条路径原则）

**问题**：我准备的备用路径真的独立吗？

**实现**：
```python
def validate_backup_paths(g, entries, objectives, paths):
    """校验备用路径：任意两条路径的节点交集必须为空"""
    conflicts = []
    for i, p1 in enumerate(paths):
        for j, p2 in enumerate(paths[i+1:], start=i+1):
            overlap = set(p1) & set(p2)
            if overlap:
                conflicts.append({
                    "path_a": i, "path_b": j,
                    "shared_nodes": list(overlap),
                    "advice": f"路径 {i+1} 与 {j+1} 共用节点 {list(overlap)}，"
                              f"防守方只需封一处即可同时切断两条链"
                })
    return conflicts
```

**这个功能直接对应 redteam-master 里的「两条路径」思维模型**——但工具把它变成了可验证的机械检查，而不是靠人脑记。**这就是「用工程化思维替代口诀」的证明，面试可讲。**

### 算法 4｜检测面覆盖分析（防守视角）

**问题**：这条攻击链里，哪些环节我是瞎的？

```python
def detection_gap(g, nodes):
    """检测盲区：detectability 为 low 或空的节点"""
    gaps = []
    for n in g.nodes():
        info = nodes[n]
        if info.get("detectability") in ("low", None, ""):
            gaps.append({
                "node": n,
                "name": info["name"],
                "risk": "防守方在此处无有效检测手段",
                "suggestion": "建议补充监控或调整攻击路径"
            })
    return gaps
```

**这是这个项目最有价值的功能**——它把「红队视角」和「防守视角」在一次计算里同时给出。面试时可以这么说：

> 「大部分攻击链工具是给红队画进攻路线，我的工具同时会告诉你这条路上防守方哪里是瞎的——因为如果我打点选在防守盲区，整条链的成功率会高得多。」

## 六、渲染设计（Graphviz）

### 6.1 DOT 生成

```python
def to_dot(chain, g, highlight=None):
    """生成 DOT，节点按战术着色，路径高亮"""
    lines = ["digraph AttackChain {",
             "  rankdir=TB;",
             '  graph [fontname="Microsoft YaHei", bgcolor="white"];',
             '  node [shape=box, style="rounded,filled", fontname="Microsoft YaHei"];']

    for node_id in g.nodes():
        n = chain.nodes[node_id]
        color = TACTIC_COLOR.get(n["tactic"], "#CCCCCC")
        label = f'{n["name"]}\\n[{n["technique"]}]\\n检测:{n["detectability"]}'
        lines.append(f'  "{node_id}" [label="{label}", fillcolor="{color}"];')

    for u, v, data in g.edges(data=True):
        style = "bold,color=red" if highlight and u in highlight and v in highlight else "color=gray"
        lines.append(f'  "{u}" -> "{v}" [{style}];')

    lines.append("}")
    return "\n".join(lines)
```

## 十、面试话术

**30 秒版：**

> 「渗透报告最难写的不是单个漏洞，是把五个漏洞串成一条完整路径。我写了这个工具，输入攻击技术节点自动出图，并且会算出三件事：最短路径——防守方在哪一点设卡我就断了；单点故障——哪一点被打掉整条链就废；以及这条路上防守方的检测盲区。这三个结果对应红队的『两条路径原则』和防守方的『纵深防御』，我把口诀变成了可验证的计算。」

**深挖版（面试官问「算法怎么实现的」）：**

> 「最短路径用的是多源最短路径的技巧——加一个超级源节点连所有入口，这样只跑一次算法而不是循环跑 N 次。SPOF 用的是节点删除法：逐个移除节点，看还存不存在完整路径，但这个是 O(V×(V+E))，节点多的话我会先用割点算法预筛一遍，只对割点做验证，这样能把开销降一个量级。」

**深挖版（面试官问「你怎么保证备用路径真的独立」）：**

> 「我把它写成了机械检查：任意两条路径的节点集合交集必须为空。因为实战里最容易犯的错是以为自己准备了两条路，实际上两条路都经过同一个文件上传点——防守方封一处就同时切断两条。我在红队演练里见过这种情况。」

## 十一、常见踩坑

| 坑 | 现象 | 解决 |
|---|---|---|
| Graphviz 中文乱码 | 图里中文变成方块 | DOT 里指定 `fontname="Microsoft YaHei"`，且系统要装该字体 |
| Windows 找不到 dot | `FileNotFoundError: dot` | 装 Graphviz 并把 `bin` 加进 PATH；或在代码里用 `dot` 路径回退 |
| SPOF 逻辑写错 | 把入口节点也报成单点故障 | 循环里先 `continue` 掉 entry/objective |
| 网络图有环 | `ValueError: Directed Graph not a DAG` | 先转无向图做连通性判断，或用 `nx.DiGraph` 并显式处理环 |
| impact 权重算不出最短路 | 所有边权都是 1 | 用 `weight="cost"` 且每条边必须有 cost 属性，否则会静默忽略权重 |
| YAML 字段名写错 | 解析成功但全是 None | `loader.py` 里加必填字段校验，缺失直接报错并提示行号 |

### 13.4 权重口径的实测语义确认

- `balanced`：检测成本×失败惩罚÷收益折让，攻方 ROI 视角（默认）；
- `stealth`：只看检测度，纯隐蔽路线（本例与 balanced 同路线，因 RDP 链检测加权总和最低）；
- `impact` / `hops`：收益最大化 / 最少跳数，用于对照推演。
