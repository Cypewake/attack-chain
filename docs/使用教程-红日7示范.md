# attack-chain 使用教程 —— 以红日 VulnStack 7 全流程为示范

> 本文回答一个问题：**拿到一个靶场/演练的红队流程后，怎么用 attack-chain 把它变成可计算的攻防地图**。
> 以红日 VulnStack 7（三层网络：外网 Redis → 内网1 跳板 → 内网2 域控）为完整示范。
> 所有命令与输出均为本机实跑结果（2026-10-19），拓扑细节对照多篇公开 walkthrough 核实。

---

## 0. attack-chain 是什么

它**不含任何扫描/利用代码**，只做一件事：把你建模的攻击链当成**有向图**来算，回答四个防守方最关心的问题：

| 问题 | 算法 | 实战含义 |
|---|---|---|
| 最短攻击路径是什么？成功率多高？ | 加权最短路径 + 乘法成功率 | 防守方要在最短路径上设卡 |
| 有没有单点故障（SPOF）？ | 割点检测 | 打掉它整链归零的点，优先加固 |
| 入口被封还有几条备用路？ | 节点不相交路径 | 红队是否有第二手，蓝队封一个点够不够 |
| 哪些环节防守是瞎的？ | 可检测性标注 | 检测盲区 = 攻击链的"舒适区"，优先补传感器 |

## 1. 三步上手

```bash
pip install -r requirements.txt          # networkx + PyYAML + Pillow，无 Graphviz 依赖

# 第一步：把攻击流程写成 YAML（建模，见下节）
# 第二步：跑分析
python -m attackchain --input examples/vulnstack7-chain.yaml --out report-v7 --weight balanced
# 第三步：读 report-v7/report.md 与 attack-chain.png，或对特定节点做防守模拟
python -m attackchain --input examples/vulnstack7-chain.yaml --out report-v7-block --block web2-laravel
```

`--out` 目录会得到：`attack-chain.svg/.png/.dot/.mmd` 四种图 + `report.md` 九章报告。

## 2. 第一步：建模 —— 把红日7 流程翻译成图

### 2.1 靶场拓扑（先弄清"地图"再画"路线"）

```
外网(Kali) ── Web1 [192.168.59.141 / 192.168.52.10]  Linux，Nginx + Redis(6379 未授权)
                │
        内网1 [192.168.52.0/24]
                ├── Web2 [52.20]  Laravel(CVE-2021-3129) + Docker，双网卡 → 93.10
                └── PC1  [52.30]  通达OA，Windows，双网卡 → 93.20
                │
        内网2 [192.168.93.0/24]  域 whoamianony.org
                ├── DC  [93.30]  Windows Server 2012 R2（最终目标）
                └── PC2 [93.40]  Windows 7，MS17-010 未打补丁
```

### 2.2 建模心法：节点 = 战术动作，边 = 跃迁条件，三率 = 成本模型

**节点**回答"做一个什么动作"：`tactic`（ATT&CK 战术）+ `technique`（技术编号）+ `kind`（角色）：

| 字段 | 红日7 示例 | 取值要点 |
|---|---|---|
| `kind` | Redis 打点 = `entry`；通 OA 拿 PC1 = `lateral`；域管 = `objective` | entry / foothold / lateral / optional / objective 五种 |
| `detectability` | 通达 OA 漏洞 = `medium`；永恒之蓝 = `high`；内网扫描 = `low` | high 会让这条边在 stealth 口径下变"贵" |
| `impact` | 抓到域管明文 = 5；内网探测 = 2 | impact 口径下高收益节点优先 |
| `fail_rate` | Docker 逃逸 = 0.45；Redis 未授权 = 0.1 | 按公开 PoC 命中率诚实估值，别全填 0.1 |

**边**回答"从 A 到 B 需要什么条件"：`condition` 写清跃迁前提（如"PC2 未装 MS17-010 补丁"），`fail_rate` 是这一跳本身的失败率。

**三率**（节点 fail_rate、边 fail_rate、detectability）共同构成成本模型 —— 整链成功率 = 全部节点与边的 `(1-fail_rate)` 连乘，所以 **15 步的链每步 90% 也只剩约 20%**，这就是"攻击链越长越脆弱"的定量表达。

### 2.3 红日7 建模的两个关键取舍

**取舍一：跳板二选一 → 两条分支 + 汇聚点。** Web2（Laravel+Docker 逃逸+FRP）与 PC1（通达OA 直连 93 段）是互斥路线，在"内网2 存活探测"汇聚：

```yaml
  - id: recon-93
    requires: [frp-proxy, pc1-cred]   # 两条入边 —— 最短路径自动二选一
```

**取舍二：真实防御对抗要建模成节点。** 实战中 psexec 打域控被防火墙挡住，逼出"先关防守再打"——这不是边上的注释，而是独立节点：

```yaml
  - id: fw-off-dc
    name: 远程关闭域控防火墙
    tactic: Defense Evasion
    technique: T1562.001
    condition: 经 IPC$ 创建服务执行 netsh（事件 7045 会留痕）
```

完整 15 节点建模见 [`examples/vulnstack7-chain.yaml`](../examples/vulnstack7-chain.yaml)（节点逐个带 detect_tips 检测建议与 note 实战注解）。

## 3. 第二步：跑分析 —— 实跑输出逐行读

`python -m attackchain --input examples/vulnstack7-chain.yaml --out report-v7 --weight balanced` 实跑输出：

```
攻击链：VulnStack7 三层靶场攻击链  (15 节点 / 16 边)
最短路径：
  1. Redis 未授权访问打点    [T1190]   检测:medium 失败率:10%
  2. 写 crontab/SSH key 拿 Web1 shell [T1053] 检测:low  失败率:15%
  3. Web1 双网卡发现与内网1 探测 [T1018]  检测:low   失败率:10%
  4. 通达 OA 漏洞打 PC1（备选跳板） [T1210]  检测:medium 失败率:30%
  5. PC1 抓取本机与域凭据     [T1003.001] 检测:medium 失败率:20%
  6. 内网2 存活探测与 SMB 指纹 [T1018]   检测:low   失败率:15%
  7. 永恒之蓝打 PC2        [T1210]    检测:high  失败率:30%
  8. PC2 mimikatz 抓域管明文 [T1003.001] 检测:medium 失败率:15%
  9. 远程关闭域控防火墙        [T1562.001] 检测:medium 失败率:25%
  10. Psexec/SMB 登录域控  [T1021.002] 检测:high  失败率:20%
  11. 域管理员权限（whoamianony.org） [T1068] 检测:medium 失败率:5%
  → 综合代价 14.013，整链成功率 1.50%

单点故障(6)：PC2 mimikatz 抓域管明文、永恒之蓝打 PC2、Psexec/SMB 登录域控、
             内网2 存活探测与 SMB 指纹、Web1 双网卡发现与内网1 探测、写 crontab/SSH key 拿 Web1 shell
最优设卡点：PC2 mimikatz 抓域管明文 (覆盖 100% 路径)
可用独立路径：1 条（两两节点不相交：是）
检测盲区：4 个 写 crontab/SSH key 拿 Web1 shell、Web1 双网卡发现与内网1 探测、
          Docker 逃逸拿 Web2 宿主、内网2 存活探测与 SMB 指纹
```

**三个值得停下来想的地方**：

1. **工具选了通达 OA 跳板（B 线），不是 Laravel（A 线）。** balanced 口径下 A 线要多付 Docker 逃逸（fail 0.45）+ FRP 代理两步的代价，而 B 线一台 Windows 直达 93 段还能直接 mimikatz —— 工具算出的"省力路线"与实战 walkthrough 的主流打法一致，说明成本模型没失真。
2. **整链成功率 1.50%。** 每步失败率都不高，但 11 步连乘后只剩 1.5% —— 这正是红队"准备多手方案"的定量理由，也解释了为什么实际打 A 段不通就换 B 段。
3. **可用独立路径只有 1 条。** 两条跳板路线在 `recon-93` 汇聚，汇聚点之后共享 —— 所以"封掉 mimikatz 抓凭据"这一个点就能切断 100% 路径。**分支多 ≠ 备用路径多，节点不相交才是硬指标。**

### 权重口径：换一个问题就换一个 `--weight`

| 口径 | 优化目标 | 红日7 实跑结果 |
|---|---|---|
| `balanced`（默认） | 攻方 ROI（成本×收益折中） | B 线，代价 14.013 |
| `stealth` | 最隐蔽（high 检测度边变贵） | 同为 B 线，代价升到 16.5 —— 永恒之蓝(psexec 的 high 检测度)拉高了成本 |
| `impact` | 收益最大 | 偏向高 impact 节点的路线 |
| `hops` | 最少跳数 | 忽略成本只看步数 |

## 4. 第三步：防守模拟 —— `--block` 回答"设卡在哪"

```bash
# 封 Laravel 跳板（A 线入口）
python -m attackchain --input examples/vulnstack7-chain.yaml --out report-v7-block --block web2-laravel
```

实跑结论：**封锁 Laravel → 链路仍可达**（剩余 1 条完整路径，最短 11 跳）—— PC1 通达 OA 线兜底了。这正是"节点不相交路径"的现实意义：**只堵一个跳板是防不住红日7 的，必须堵共同必经点**。

而不带 `--block` 运行时，工具会对前 3 个最优卡点自动做封锁模拟（实跑全部"已切断"）：`PC2 mimikatz`、`永恒之蓝`、`psexec` —— 三个点全在内网2 汇聚段之后。**防守启示：在 93 段做主机加固（打 MS17-010 补丁 + LSASS 保护 + 域管不得登录低信任主机）比在外网堆 WAF 收益更高。**

## 5. 报告九章导读

`report.md` 自动生成的九章，各有用途：

| 章节 | 回答什么 | 复盘时怎么用 |
|---|---|---|
| 一、攻击链图 | 全景拓扑（红边=最短路径） | 贴进复盘文档当封面 |
| 二、结论摘要 | 上面控制台输出的完整版 | 给领导/队友的 30 秒版本 |
| 三、ATT&CK 技术映射 | 每节点 → 技术编号 → 建议数据源 | 直接产出检测需求清单 |
| 四、最短路径明细 | 每步的跃迁条件与失败率 | 对照实况：哪步实际失败了？ |
| 五、SPOF 分析 | 6 个单点故障 | 加固优先级列表 |
| 六、防守卡点排序 | 按路径覆盖率排序的设卡点 | 蜜罐/告警埋点选址 |
| 七、备用路径校验 | 封某点后还剩几条路 | 演练"封了之后红队怎么走" |
| 八、检测覆盖面 | 全链检测盲区 4 处 | 传感器补盲清单 |
| 九、防守阻断模拟 | 每个卡点封锁后的可达性 | 防守方案的验证记录 |

## 6. 常见问题

- **技术编号告警怎么处理？** 报告会提示"战术声明与技术归属不一致"或"不在本地子集"——前者像红日8 示例故意保留的 T1110.001 归属讨论（预期行为），后者按需扩展 `data/tactics.json`。红日7 示范已顺手补登记了 `T1210`（远程服务利用）与 `T1562.001`（防御规避），照着 JSON 格式加即可。
- **ATT&CK 正式编号与本地子集不一致的近似怎么标注？** 写进节点 `note`。如 Docker 逃逸正式编号是 T1611(Escape to Host)，本地子集以 T1068 概括；Redis 写 SSH key 正式编号是 T1098.004，以 T1053 概括。
- **图里节点顺序看着"乱"？** 内置布局器按战术阶段分层（不依赖 Graphviz），分支多的图会牺牲一点美观换零依赖。要出版级布局：`--format dot` 后用本地 Graphviz 重渲染 `.dot` 文件。
- **optional 节点什么时候用？** 可以放弃的旁路（如 C2 持久化）标 `kind: optional`，失败不阻断主链分析。
